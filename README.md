# AIDC Simulator — 울산 AI 데이터센터 운영 시뮬레이션

> 현재 버전: **v0.4** (2026-10-29) · Python / Tkinter / SQLite · 추가 패키지 없음

가상의 울산 AI 데이터센터 운영 직원이 되어 싱가포르·일본·미국 고객의 요청을 처리하는 미션 게임입니다. 제한된 GPU와 전력을 배분하고, 고객마다 발생한 네트워크 장애에 대응해 운영 점수를 얻습니다.

고객사, 사건, 자원 수치와 네트워크는 교육용 가상 설정입니다. 실제 데이터센터나 외부 네트워크에 접속하지 않습니다.

## 실행

Python 3.10 이상과 Tkinter가 필요합니다. 프로젝트 폴더에서 실행하세요.

```powershell
python main.py
```

현재 PC처럼 `python`이 Windows 실행 별칭으로 연결되어 실행되지 않으면 설치된 Anaconda Python을 사용할 수 있습니다.

```powershell
& "$env:USERPROFILE\anaconda3\python.exe" main.py
```

Tkinter 설치 여부는 같은 실행 파일로 `-m tkinter`를 실행해 확인할 수 있습니다. 새로운 pip 패키지나 외부 GUI 라이브러리를 설치할 필요가 없습니다.

첫 실행 시 프로젝트 폴더에 `aidc_game.db`가 생성됩니다. 기존 DB가 있으면 고객·미션·수행 기록·이벤트 로그를 유지합니다.

## 플레이 방법

1. 왼쪽의 고객 카드를 선택하고 요청 내용과 자원 요구량을 확인합니다.
2. 하단에서 고성능 또는 절약형 모드를 선택하면 GPU와 전력을 배정합니다.
3. 국제 네트워크 장애가 발생합니다. 대응하기 전에 다른 고객 카드나 지도 노드를 선택해 다른 작업을 시작할 수 있습니다.
4. 장애가 있는 고객으로 돌아와 백업 경로, 압축, 기존 설정 유지 중 하나를 선택합니다.
5. 대응 직후 성공/실패와 점수가 표시되고 **그 작업의 자원만 반환**됩니다. 같은 고객의 새 요청을 받거나 다른 고객의 작업을 이어가세요.

시간이 지나도 미션이 자동으로 끝나지 않는 턴 기반 게임입니다. 네트워크의 움직이는 점과 우회선은 시각 효과입니다.

## 고객별 자원 요구량

총 GPU는 **10개**, 전력은 **10단위**입니다. GPU와 전력은 모든 작업이 공유합니다. 네트워크 가용량은 고객별로 독립적이며 공유 자원에서 차감하지 않습니다.

| 고객 / 작업 | 모드 | GPU | 전력 | 필요 네트워크 |
| --- | --- | ---: | ---: | ---: |
| 싱가포르 · Merlion AI / 모델 학습 | 고성능 | 7 | 7 | 5 |
| 싱가포르 · Merlion AI / 모델 학습 | 절약형 | 4 | 4 | 3 |
| 일본 · Sakura Robotics / 로봇 AI 추론 | 고성능 | 3 | 4 | 3 |
| 일본 · Sakura Robotics / 로봇 AI 추론 | 절약형 | 2 | 2 | 2 |
| 미국 · Northstar AI / 데이터 분석 | 고성능 | 6 | 6 | 6 |
| 미국 · Northstar AI / 데이터 분석 | 절약형 | 4 | 3 | 5 |

일본은 적은 자원으로 안정적으로 처리할 수 있습니다. 고성능 모드에서도 압축 대응이 성공합니다. 싱가포르는 절약형+압축이 성공하지만 고성능+압축은 실패합니다. 미국은 두 모드 모두 압축만으로는 부족하여 백업 경로가 필요합니다. 고성능 모드는 점수 보너스가 크고 절약형은 다른 고객에게 남겨줄 자원이 많습니다.

예를 들어 일본 고성능과 미국 고성능을 함께 실행하면 GPU 9개와 전력 10단위를 점유합니다. 싱가포르 요청은 한 작업을 완료해 자원을 반환해야 시작할 수 있습니다. 세 고객을 모두 절약형으로 시작하면 GPU 10개, 전력 9단위를 점유합니다.

기존 DB에 사용자 추가 고객이 있다면 기본 싱가포르 규칙을 사용합니다. 같은 미션의 중복 시작과 진행 중 재시작은 차단됩니다.

## 장애 대응과 점수

정상 네트워크 가용량은 8, 장애 시에는 해당 고객의 가용량이 2가 됩니다.

| 대응 | 효과 | 점수 차감 |
| --- | --- | ---: |
| 백업 경로로 우회 | 가용량 +4, 최대 8 | 15 |
| 전송 데이터 압축 | 필요량 −2, 최소 1 | 10 |
| 기존 설정 유지 | 변화 없음 | 25 |

대응 후 **필요량 ≤ 가용량**이면 성공합니다. 하단 버튼에 대응 후의 필요량과 가용량을 미리 표시합니다. 유지 선택의 차감은 장애를 방치하는 운영 손실을 뜻합니다.

점수는 `80 + 모드 보너스 − 대응 차감 + 결과 보정`을 0~100으로 제한합니다. 모드 보너스는 고성능 15, 절약형 5이며, 결과 보정은 성공 +10, 실패 −65입니다. 기존 싱가포르 규칙과 과거 점수는 유지합니다. 종료로 중단한 작업은 별도로 0점 처리합니다.

## 관제실 화면

- **왼쪽:** 국가·고객사·요청·두 모드 요구량·작업 상태를 표시하는 미션 카드
- **중앙:** 울산 AIDC와 해외 고객의 가상 연결망. 장애는 붉은 선과 경고, 백업은 움직이는 청록색 우회선, 성공은 초록색 상태로 표시
- **오른쪽:** GPU 10개 서버 블록과 전력 게이지. 고객별 색상과 숫자로 점유량 표시
- **하단:** 선택 고객의 상세 요청과 상황별 행동, 고객별 이벤트 및 전체 수행 기록 탭
- 자원 부족 모드는 비활성화하고 부족한 GPU·전력을 표시합니다. 마우스를 올리면 버튼 피드백과 간단한 도움말이 나옵니다.
- 최소 창 크기는 980×680입니다. 창이 작으면 오른쪽 세로 스크롤이나 마우스 휠로 하단까지 이동하세요. 기록 표는 가로·세로 스크롤을 지원합니다.
- 전체 수행 기록에는 최근 30건을 표시합니다. 기록을 더블클릭하면 해당 수행의 상세 로그를 볼 수 있습니다. 그보다 오래된 데이터도 DB에 보존됩니다.

## 저장 및 종료 정책

작업 시작·대응과 관련 로그를 함께 저장합니다. 저장이 실패하면 자원과 게임 상태를 이전 상태로 되돌려 재시도할 수 있습니다.

- **창을 정상 종료:** 이번 실행에서 진행 중인 작업을 실패·0점, 대응 `abandon`으로 저장하고 자원을 반환합니다. 완료 기록은 유지합니다.
- **종료 기록 저장 실패:** 창을 닫지 않고 오류를 알려줍니다. 다시 종료하거나 작업을 완료할 수 있습니다.
- **강제 종료·이전 버전에서 남은 진행 기록:** DB 행과 로그를 그대로 보존하고 수행 기록에 `이전 실행 미완료`로 표시합니다. 자동 재개하거나 실패로 덮어쓰지 않습니다.
- **다시 실행:** GPU와 전력은 모두 비어 있고 고객 요청은 대기 상태로 시작합니다. 미완료 작업의 자동 복원은 지원하지 않습니다.

DB 테이블 구조를 변경하지 않아 v0.2/v0.3 데이터를 그대로 사용할 수 있습니다. 기존 미션 ID와 수행 기록 연결도 유지합니다.

## 테스트

```powershell
python -m unittest discover -s tests -v
```

Anaconda 실행 파일을 사용하는 경우:

```powershell
& "$env:USERPROFILE\anaconda3\python.exe" -m unittest discover -s tests -v
```

**52개 테스트 통과**: 기존 30개에서 변경된 전환·고객별 규칙을 반영하고, 요구량 5개·동시 미션 및 종료 정책 11개·실제 Tk GUI 6개 검증을 추가했습니다. 모든 DB 테스트는 메모리 DB 또는 임시 파일 DB를 사용합니다. 실제 `aidc_game.db`를 초기화하거나 테스트에 사용하지 않습니다.

Tk 화면을 사용할 수 없는 환경에서는 GUI 테스트 6개가 사유를 표시하고 건너뜁니다. 이번 Windows 환경에서는 건너뛰기 없이 실행했습니다. 980×680, 1100×760, 1360×940에서 패널 폭과 스크롤 접근을 확인했습니다. 사용자 환경의 고배율 DPI, 다중 모니터, 장시간 플레이의 체감은 추가 수동 확인 대상입니다.

## 파일 구조

| 파일 | 역할 |
| --- | --- |
| `main.py` | 화면 배치, 고객 선택과 버튼 이벤트, 기록 조회 |
| `ui.py` | 미션 카드, 네트워크 지도, 자원 패널, 스크롤·버튼·도움말 |
| `session.py` | 고객별 상태, 공유 데이터센터, 저장 실패 복구, 종료 정책 |
| `game.py` | 고객별 요구량, 자원 배정·반환, 장애 대응과 점수 |
| `database.py` | SQLite 테이블·기본 데이터, 저장 트랜잭션, 기록 조회 |
| `tests/` | 규칙·데이터 보존·동시 미션·저장 복구·GUI 검증 |

DB 관계는 `clients 1:N missions 1:N playthroughs 1:N event_logs`입니다.
